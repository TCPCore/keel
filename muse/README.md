# Muse Code briefs

Every piece of code in `src/keel` that is not in this repository's foundation
commits is generated by Muse Code from a brief in this directory, then audited by
a human before it is committed. The gate is in `scripts/audit_gate.py`.

## The loop

```
brief  →  branch agent/NN-name  →  Muse Code generates
       →  make audit (test + lint + diffstat)
       →  human review against the brief
       →  audit/NN-name.md signed
       →  commit with --trailer "Audited-by: <name>"
```

Nothing is pushed without the trailer. The pre-push hook enforces it.

## Brief format

Every brief is self-contained, because the agent does not share this
conversation. Seven sections, in this order:

1. **Context** — one paragraph: what Keel is, what this task is for.
2. **Allowed files** — the exact files it may create or modify. Anything else is
   out of scope and is grounds for rejection.
3. **Interfaces** — signatures, dataclasses, return types, error behaviour. Copied
   from the existing code so the agent cannot invent a parallel API.
4. **Constraints** — dependency limits, lazy imports, no network at import, no
   secrets, determinism and seeds.
5. **Acceptance** — commands that must pass, and tests it must add.
6. **Non-goals** — what it must not attempt, especially scope it might invent.
7. **Audit checklist** — the specific things a human will check, beyond the
   generic list in `audit/_TEMPLATE.md`.

## Install

The CLI installs entirely inside the repo; nothing touches your home directory
and the 428 MB binary is gitignored.

```bash
curl -fsSL https://dev.meta.ai/install.sh -o .tools/meta-install.sh
MUSE_INSTALL_DIR="$PWD/.tools/bin" MUSE_NO_MODIFY_PATH=1 bash .tools/meta-install.sh
```

Verify both surfaces:

```bash
python scripts/muse_smoke.py     # raw Model API: base URL, models, one completion
scripts/muse_run.sh --smoke      # the CLI headlessly, same key
```

`muse exec` accepts `--api-key-stdin` with `--provider meta`, so the Model API key
is enough — no OAuth device login is needed for headless runs. The key is read
from `.env` and piped over stdin, so it never lands in argv or shell history.

## Running a brief

```bash
scripts/muse_run.sh muse/01-whitebox-core.md
```

Output is JSONL under `.tools/runs/<task>/events.jsonl`. The agent gets
`--workspace` rooted at the repo, so it can edit files; the audit gate is what
decides whether those edits are committed.
